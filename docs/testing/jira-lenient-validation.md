# JIRA 简短 RCA 质量评估：标定与发布门槛

## 测量对象
`jira_lenient_v1_4` 衡量 JIRA **短文本可用性**；不测量技术根因真实性或修复有效性。严格模式继续负责取证验证，分数不能直接相互换算。

## 测试分层

1. **契约单测**：结果锚点、计分、阈值、强制人工复核、错误输入、模式分流和兼容性。可自动化。
2. **合成语义样本**：至少 50 个软件缺陷短文本，覆盖代码/接口/配置/测试/环境/竞态/权限/兼容/回归/人员归因、规避与真正修复、1 句和 3 句。用于发现提示词偏差，**不是**准确率证据。
3. **真实 JIRA 盲测**：从实际系统抽取至少 50 条去标识根因/方案，按缺陷类型及历史状态分层。训练/修改与最终留出集分离（建议 >=20%）。
4. **人工基准**：两位有经验评审独立给出「通过/不通过」、「根因已验证?/未知」、「错误放行风险」及理由；对分歧仲裁后锁定金标准。
5. **模型重复性**：固定模型、提示词、温度设置（可控时）和样本顺序，至少重复 3 轮。保存逐例输出与版本 SHA；统计分数漂移及阈值翻转。

## 最低报告指标

- 通过率和人工通过率，按 bug 类型分层，避免只看总体通过率。
- 假通过（人工拒绝、Agent 自动放行）率，特别追踪纯空话、明显矛盾和危险修复。
- 假拒绝（人工准入、Agent 拒绝）率，目标是减少原严格模式对短文本的不公平拒绝。
- `technical_verification=verified` 的误标率必须为 0（宽松文本模式禁止此值）。
- 重复运行一致率及每例分数最大变化。
- 所有人工复核覆盖与原因；模型未返回或解析失败分别计入失败，不能从分母消失。

## 发布建议（尚未经标定）

只有在真实样本误放行分析完成、运行入口和包内容测试通过后，才考虑对外发布并更新主版本。30/60 是试行阈值，可以针对真实数据调整；不要事后用同一批样本既调参又宣称效果。

## 数据保护

在本地授权环境脱敏处理真实 JIRA；不把内部代码、密钥、客户信息上传到公开仓库。公开仓库只保留合成用例与不含隐私的汇总指标。
