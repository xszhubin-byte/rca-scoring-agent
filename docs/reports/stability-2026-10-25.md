# 固定输入评分稳定性复测（2026-10-25）

候选版本 **2.0.0-alpha.5** 在下述固定条件下通过预设重复性门槛：12 例 × 3 轮，
36 份评判全部被接受；9 次独立 Codex CLI 调用的输入、设置、运行资源及响应记录核对通过。
这是一项重复性结果，尚不能证明专家准确率、六领域最优性或生产事故适用性。

## 配置与独立性

- Codex CLI `0.164.0-alpha.11.1`，显式请求 `gpt-6-astra`，推理 `medium`。
- 每批 4 例，固定批次顺序；每次新会话，不使用工具、网络或历史响应。
- 8 例合成边界输入，4 例真实公开补丁的产物审查。不是 50 例的三轮 V2 模型验收。
- 运行资源、输入、输出格式冻结。预期行为单独保存，不发送正确状态或分数。
- CLI 未提供底层模型 snapshot ID，不能保证未来后端版本不变。

每案例轮次两两评分绝对差均值不超过 0.25 档。没有修改门槛、截断分数、投票替换或拼接轮次。

## 开发失败没有删除

| 批次 | 发现及处理 |
|---|---|
| baseline-fixed-model | 无作者原文却判作者漏写；保留失败，明确模式边界。 |
| mode-contract-alpha2 | K07 的测试期望错误地强制 needs_evidence；移除错误期望，保留原始正确响应。 |
| acceptance-alpha2 | 同输入状态/评分漂移；K08 把可复核的失败执行误判为未执行。 |
| contract-v1-alpha3 | 固定来源约定后仍出现 2–3 档波动；停止该批次，保留已完成响应。 |
| astra-contract-alpha4 | 完整 36 份评判，12 例中仅 9 例达标；K07/C4、K08/C4、K11/V3 超过一档，判失败。 |
| astra-full-evidence-alpha5 | 修正合成材料内部冲突，补充当前版本完整测试函数；重新独立完成三轮，12/12 达标。 |

模型、来源约定及锚点在开发阶段有多项变化，不能单独归因某一变化。所有开发失败属于
调试数据，当前 12 例也是迭代过的开发验收集，存在对该集合过拟合风险，不是独立留出验证。

## 补充的代码证据与验证限制

从固定 head 提交获取 5 份真实测试文件，核对 Git blob SHA，抽取与差异相关的 7 个完整函数。
包含当前版本中未修改的断言，避免仅靠差异新增行推断测试覆盖；仍不包含完整测试依赖或项目。
公开原文件在 [test-sources.json](../../data/stability/evidence/test-sources.json)。

本次没有运行上游 Go 测试，没有生产复现日志、完整引入历史、长期效果观测或独立专家双盲标签。
合成成功/失败记录只用于检查证据门槛，绝不是实际上游执行证明。缺失执行证据的真实案例
仍停留在 implemented。CI 绿灯不能替代特定缺陷测试的实际执行证据。

尚未测量自由文本陈述抽取、任意改写/排序/批大小、其他模型、其他缺陷分布或未来模型快照的稳定性。
六领域与 24 项是可诊断的候选结构，不声称已证明优于所有五维方案，也不生成有掩盖作用的综合分。

python tools/calibration/verify_stability.py data/stability/NEW-COHORT --private-events ../private-codex-runs/NEW-COHORT

新标签保留每次运行，失败不自动重试。复现需调用者已登录的 Codex CLI 和相应模型额度。
会话标识仅公布 SHA-256；原始本机日志及凭据不进入源码和版本包。
